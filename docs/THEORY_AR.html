دليل مختصر للمناقشة: شرح بالعربي، مع بقاء المصطلحات والمعادلات بالإنجليزي. الأمثلة من الداتا الأصلية: 10 documents.

1. How do positions support phrase queries?

الـ term-only index يثبت إن الكلمات موجودة في الملف، لكن ما يثبتش ترتيبها أو إنها جنب بعض. عشان نطابق phrase، بنستخدم الـ Positional Index ونتأكد إن الكلمات في نفس الـ document، بنفس الترتيب، وفي consecutive positions. العد بيبدأ من 1.

في d5، كلمة machine عند [1, 3, 9]، وكلمة learning عند [2, 10]. إذن machine learning بتبدأ عند [1, 9]، والـ ranges هي 1–2 و9–10. عند 3 الكلمة اللي بعدها models، فمفيش تطابق.

الفكرة الأساسية: بنفحص الـ positions في الـ index، مش مجرد وجود الكلمات أو البحث بـ substring في النص.

2. How are DF and IDF related, and why does repetition affect TF?

TF هو عدد مرات ظهور الكلمة داخل document واحد. أما DF فهو عدد الـ distinct documents اللي فيها الكلمة؛ تكرارها في نفس الملف ما يزودش مساهمة الملف في DF عن واحد.

IDF(t) = log10(N / DF(t)),   N = 10
Weighted TF = 1 + log10(TF) if TF > 0; otherwise 0

كل ما DF يزيد، IDF يقل؛ لأن الكلمة المنتشرة أقل قدرة على تمييز ملف. كلمة data موجودة في 7 documents، فـ IDF ≈ 0.1549. كلمة science في 3 documents، فـ IDF ≈ 0.5229.

كلمة machine متكررة 3 مرات في d5، إذن TF = 3 وWeighted TF ≈ 1.4771، لكن d5 يضيف واحد بس لـ DF. الـ logarithm يخلي التكرار مفيد من غير مبالغة في وزنه.

3. Why use TF-IDF and vector normalization?

TF-IDF بيجمع أهمية الكلمة داخل الملف مع ندرتها في الـ collection. أما Normalization فبيقسم كل وزن على L2 norm للـ vector، عشان المقارنة تبقى حسب الاتجاه، مش مقدار الأوزان بس.

TF-IDF(t,d) = Weighted TF(t,d) × IDF(t)
Length(d) = √(Σₜ TF-IDF(t,d)²)
Normalized TF-IDF(t,d) = TF-IDF(t,d) / Length(d)

بكده الملف الأطول ما ياخدش score أعلى لمجرد إن عنده كلمات أكتر. مجموع مربعات أوزان أي nonzero normalized vector يساوي 1. لو الـ length = 0، بنسيب الأوزان صفر لتجنب القسمة على صفر.

4. How do similarity scores rank documents?

الأول بنحدد الملفات اللي حققت الـ phrase أو الـ Boolean condition. بعد كده بنحسب Cosine Similarity بين الـ query vector وكل document vector. لما الاتنين يكونوا L2-normalized، الـ Cosine Similarity تساوي الـ dot product:

Similarity(q,d) = Σₜ NormalizedQuery(t) × NormalizedDocument(t,d)

بنضرب الأوزان المقابلة لنفس الكلمة، وبنجمع النواتج. بنرتّب الـ matching documents من أعلى score لأقل. ولو حصل تعادل، بنستخدم رقم الـ document تصاعديًا عشان الترتيب يبقى ثابت.

مع machine learning، الملف d1 هو نفس الـ query، فالاتجاه واحد والـ score = 1.0000. الملفات المطابقة التانية فيها أوزان لكلمات إضافية، فدرجاتها أقل:

d1 (1.0000) > d5 (0.3809) > d10 (0.3072) > d2 (0.2867) > d7 (0.2730)
تمييز مهم: الـ phrase matching يحدد مين يدخل النتيجة، والـ Cosine Similarity تحدد ترتيب اللي دخلوا. الـ query بتستخدم collection IDF، مش IDF جديد.

5. How do AND and AND NOT differ here?

هنسمي مجموعة الملفات اللي فيها machine learning باسم A، واللي فيها data science باسم B:

A = {d1, d2, d5, d7, d10}
B = {d3, d5, d8}

AND: لازم الـ document يحتوي الـ phrases الاتنين كاملين. بنعمل intersection للمجموعتين:

A ∩ B = {d5}

في الـ ranking بنستخدم كلمات الـ positive phrases الاتنين: machine, learning, data, science. درجة d5 ≈ 0.5113.

AND NOT: نحتفظ بالملفات اللي فيها أول phrase، ونستبعد اللي فيها تاني phrase كاملة. بنعمل set difference:

A − B = {d1, d2, d7, d10}
Ranking: d1 > d10 > d2 > d7

هنا الـ scoring يستخدم machine learning بس. الـ negative phrase فلتر للاستبعاد فقط؛ مش بنمسح كلماتها أو أوزانها من الـ original document vector.

ليه d2 وd10 فضلوا؟ فيهم كلمة data، لكن مفيهمش الـ phrase الكاملة data science؛ عشان كده ما بيتستبعدوش.

ملاحظة حسابية: الأرقام هنا مقربة للعرض. البرنامج بيحتفظ بالـ full precision أثناء الحساب، ويعمل rounding عند العرض فقط.
