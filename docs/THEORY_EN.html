Five theoretical explanations

Questions 1–2 · Positional indexing and term statistics

1. How do positions support phrase queries?

A term-only index tells us that words occur in a document. It does not prove that they occur in the required order or next to each other.

A Positional Index stores every occurrence of each term together with its document ID and position. A phrase matches only when its terms occur in the same document, in the correct order, at consecutive positions. Positions start at 1.

Example: d5 machine: [1, 3, 9] learning: [2, 10] Phrase: machine learning Starting positions: [1, 9] Token ranges: [1–2], [9–10]

Positions 1 and 9 are valid starts because learning occurs immediately after them, at positions 2 and 10. Position 3 is not a valid start: its next word is models.

Key point: Phrase matching checks position lists in the index. It does not substitute raw substring matching for the positional algorithm.

2. How are DF and IDF related, and why does repetition affect TF?

TF counts term occurrences within one document. DF counts distinct documents containing the term. Repeating a word in one document increases its TF, but that document still contributes only one to DF.

IDF(t) = log10(N / DF(t)), with N = 10 Weighted TF = 1 + log10(TF) when TF > 0; otherwise 0

As DF increases, IDF decreases: a widespread term is less useful for distinguishing one document from another. Logarithmic Weighted TF gives repeated terms more weight, but with diminishing returns.

data: DF = 7 → IDF ≈ 0.1549 science: DF = 3 → IDF ≈ 0.5229 machine in d5: TF = 3 → Weighted TF ≈ 1.4771

Although machine occurs three times in d5, d5 contributes only one document to its DF.

Weighting and similarity

Questions 3–4 · Vector normalization and ranking

3. Why use TF-IDF and vector normalization?

TF-IDF combines a term’s importance inside a document with its rarity across the collection. Its weight increases with weighted term frequency and collection specificity.

TF-IDF(t,d) = Weighted TF(t,d) × IDF(t) Length(d) = √(Σₜ TF-IDF(t,d)²) Normalized TF-IDF(t,d) = TF-IDF(t,d) / Length(d)

Vector Normalization divides every component by the vector’s L2 norm. This removes overall magnitude from the comparison, so a longer document does not score higher merely because it contains more words. We compare directions in the same vocabulary space.

For every nonzero normalized vector, the sum of squared components equals 1. A zero-length vector safely remains zero.

machine in d5: TF-IDF ≈ 0.4447 Document length ≈ 1.5526 Normalized weight ≈ 0.2864

4. How do similarity scores rank documents?

First identify documents satisfying the phrase or Boolean condition. Build the Query Vector from query term counts and the existing Collection IDF; do not calculate a new IDF from the query.

After both vectors are L2-normalized, Cosine Similarity equals their Dot Product: multiply corresponding term weights and sum the products.

Similarity(q,d) = Σₜ NormalizedQuery(t) × NormalizedDocument(t,d)

Sort matching documents by decreasing similarity. Break ties using ascending numeric document ID for a deterministic order.

For machine learning, d1 contains exactly the query phrase. Its vector points in the same direction as the query vector, giving a score of 1. The other matching documents also have weight on additional terms.

machine learning ranking: d1 (1.0000) > d5 (0.3809) > d10 (0.3072) > d2 (0.2867) > d7 (0.2730)
Separate the two decisions: Phrase Matching determines eligibility; Cosine Similarity determines the order of eligible documents.

Boolean retrieval

Question 5 · AND versus AND NOT

5. How do AND and AND NOT differ here?

Boolean operations apply to sets of documents matching complete phrases, rather than to isolated words. Let A and B be the following phrase-match sets:

A = matches of “machine learning” A = {d1, d2, d5, d7, d10} B = matches of “data science” B = {d3, d5, d8}

AND: require both phrases

AND returns documents containing both complete phrases. It uses set Intersection.

A ∩ B = {d5}

Both phrases are positive requirements, so their terms contribute to the ranking query vector: machine, learning, data, and science. The only result is d5, with similarity approximately 0.5113.

AND NOT: require the first phrase and exclude the second

AND NOT retains documents matching the first phrase and removes documents matching the complete second phrase. It uses Set Difference.

A − B = {d1, d2, d7, d10} Ranked results: d1 > d10 > d2 > d7

Only the positive phrase, machine learning, contributes to query weighting. The negative phrase, data science, is a filter only.

Why do d2 and d10 remain? They contain data, but do not contain the complete contiguous phrase data science. They therefore do not satisfy the exclusion condition.

The original Normalized Document Vector remains unchanged. We do not delete negative-term weights from document vectors.
